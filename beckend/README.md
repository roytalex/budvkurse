# Будь ВКурсе — бэкенд

Здесь находится API на **FastAPI + SQLAlchemy 2 + PostgreSQL**. Это серверная часть: она хранит пользователей и мероприятия, проверяет права и отдаёт данные сайту.

Начни с раздела «Запуск». Подробный справочник таблиц, схем и функций находится в `docs/REFERENCE.md`; описание запросов и подключения сайта — в `docs/API.md`. Все примеры команд ниже выполняются **из папки beckend**.

## Что уже реализовано

- 13 таблиц: пользователи, сессии, города, школы, темы, интересы, мероприятия, темы мероприятий, избранное, планы, регистрации участников, файлы и решения модератора.
- Регистрация и вход; хеширование паролей; access/refresh-токены; выход и деактивация аккаунта.
- Роли `student`, `organizer`, `admin`; проверка владельца при редактировании.
- Справочники городов, школ и тем; проверка соответствия школы городу.
- Черновики, самостоятельная публикация организатором, отмена и удаление администратором.
- Поиск, фильтры, сортировка, карта по границам видимой области и календарь по датам.
- Избранное, личные планы и запись на события с проверкой свободных мест.
- Загрузка JPEG/PNG/WEBP; проверка содержимого и размера файла.
- Миграция Alembic, демоданные, команды администратора и автоматические тесты.

Фронтенд подключён к API. Полная инструкция запуска сайта находится в START.md в корне проекта. Приложение раздаёт интерфейс и API на одном порту 4174. Все API-разделы с данными требуют входа. Поле напоминания сохраняется в БД, но фоновая отправка писем/push пока не реализована. Возраст события используется в фильтрах; проверить возраст участника нельзя, потому что в согласованной модели пользователя нет даты рождения. Класс участника проверяется при записи.

## Запуск на Windows

### 1. Открой терминал в этой папке

```powershell
cd C:\Users\roytb\Desktop\budvkurse\beckend
python --version
```

Нужен обычный Python 3.12 или новее и установленный PostgreSQL. Если `python` не найден, установи Python с пунктом «Add python.exe to PATH» и заново открой терминал.

### 2. Установи зависимости

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

`requirements-lock.txt` содержит версии, на которых проверен этот проект. Активировать окружение не обязательно: дальше везде явно указан его Python. Это также обходит проблему с запретом запуска Activate.ps1 в PowerShell.

### 3. Создай пустую базу PostgreSQL

Если у тебя уже есть **пустая** `roytalex`, можешь использовать её. Если там есть старые таблицы/данные, для первого запуска удобнее создать новую `budvkurse`, сохранив старую базу.

Для установленного PostgreSQL 17:

```powershell
& "C:\Program Files\PostgreSQL\17\bin\psql.exe" -h localhost -p 5432 -U postgres -d postgres
```

Введи пароль пользователя PostgreSQL. Затем **внутри psql**, а не в PowerShell:

```sql
CREATE DATABASE budvkurse;
\q
```

Если версия PostgreSQL другая, измени `17` в пути. Сообщение «database already exists» значит, что база уже есть: не удаляй её.

### 4. Заполни настройки

```powershell
.\.venv\Scripts\python.exe -m scripts.configure
```

Команда спросит адрес сервера, порт, имя базы, пользователя и пароль. Она создаст `.env` и случайный `JWT_SECRET`. Существующий `.env` не перезаписывается.

Пример строки подключения без настоящего пароля:

```dotenv
DATABASE_URL=postgresql+asyncpg://postgres:YOUR_PASSWORD@localhost:5432/budvkurse
```

Названия `DATABASE_URL` и `JWT_SECRET` пиши именно так. Не используй старую опечатку `DATABESE_URL`. Настройщик корректно обработает специальные символы в пароле. `.env` не добавляется в Git; образец настроек есть в `.env.example`.

### 5. Создай таблицы миграцией

```powershell
.\.venv\Scripts\python.exe -m scripts.inspect_db
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Первую миграцию применяй к пустой базе. Если `inspect_db` показал старые таблицы без `alembic_version`, не применяй `stamp head` наугад и не удаляй таблицы: используй новую базу или подготовь отдельную миграцию переноса данных. Существующая база при разработке этого бэкенда не изменялась.

### 6. Создай администратора и примеры

```powershell
.\.venv\Scripts\python.exe -m scripts.create_admin
.\.venv\Scripts\python.exe -m scripts.seed_demo --email admin@example.com
```

Во второй команде подставь email администратора, которого только что создал. Пароль задаёшь сам; готового общего пароля нет. Демоданные явно помечены «Демо», даты событий — примерно через неделю после заполнения. Повторный запуск не создаёт дубликаты.

При регистрации на сайте или через API можно выбрать `student` или `organizer`. Если роль не передана, создаётся ученик. Чтобы изменить роль существующего аккаунта:

```powershell
.\.venv\Scripts\python.exe -m scripts.set_role organizer@example.com organizer
```

После смены роли нужно войти заново. Эта команда запускается только человеком с доступом к терминалу сервера.

### 7. Запусти API

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 4174
```

Открой [Swagger](http://127.0.0.1:4174/docs). Там можно нажать ручку → **Try it out** → заполнить JSON → **Execute**. [Health](http://127.0.0.1:4174/health) проверяет подключение к БД. Терминал с сервером должен оставаться открытым; остановка — Ctrl+C.

Для защищённых ручек сначала вызови `POST /api/v1/auth/login`, скопируй `access_token` из ответа и вставь его в **Authorize**. Вставляй сам токен, без кавычек и без слова Bearer: Swagger добавит его автоматически.

## Как устроен код

```text
beckend/
  main.py                 вход в приложение; подключение всех ручек
  core/                   настройки, токены, время, ошибки
  db/
    db.py                 Base, движок БД, сессия и транзакция
    models/               SQLAlchemy-модели: какие таблицы храним
  schemas/                Pydantic: что принимаем и что возвращаем
  crud/                   запросы SELECT / INSERT / UPDATE / DELETE
  services/               правила: кто может что делать и при каких условиях
  api/
    deps.py               проверка токена, текущего пользователя и роли
    routes/               HTTP-ручки FastAPI
  migrations/             история изменений структуры БД
  scripts/                настройка, администратор, роли, демоданные
  tests/                  проверки API и одновременных запросов
  docs/                   подробный справочник
```

Путь одного запроса:

```text
Сайт → ручка FastAPI → схема проверяет входные поля
                    → сервис проверяет правила и права
                    → CRUD обращается к таблицам
                    → схема Read формирует JSON-ответ
```

Например, `POST /api/v1/events` принимает `EventCreate`. `services/events.py` проверяет город, школу, темы и обложку. `crud/events.py` создаёт строку `events`; `crud/interests.py` записывает темы в `event_topics`. В конце возвращается `EventRead`.

`get_db` открывает одну транзакцию на запрос. Если всё прошло — `commit` (сохранить); если ошибка — `rollback` (отменить изменения запроса). CRUD вызывает `flush`, чтобы получить id, но не делает самостоятельный `commit`. Поэтому мероприятие и его темы сохраняются вместе.

## Правила, которые важно понимать

| Действие | Поведение |
|---|---|
| Регистрация аккаунта | Можно выбрать `student` или `organizer`; без выбора — `student`; роль `admin` запрещена |
| Создание события | Организатор/админ создаёт `draft` |
| Публикация организатором | Свой `draft`, старый `pending` или `rejected` → `published`, без одобрения |
| Контроль администратора | Просмотр всех событий и удаление неподходящих |
| Правка опубликованного | Остаётся `published`, изменения сразу видны; обязательные поля сохраняются |
| Отмена опубликованного события | `published` → `cancelled`; карточка по прямой ссылке и история участников сохраняются |
| Удаление события | Организатор — свой черновик; администратор — любое событие. Связанные записи участников, планы, избранное и история проверки удаляются в одной транзакции |
| Удаление аккаунта/школы | Деактивация; данные не стираются каскадом |
| Удаление города/темы | При связанных данных возвращается 409 |
| Добавление в планы | Не записывает участником — это отдельная операция |
| Повторное избранное/планы | Обновляет/возвращает одну запись, без дубликатов |
| Запись на событие | Только `published`, `internal`, до дедлайна и начала; проверяются класс и места |
| Нет свободных мест | 409; блокировка PostgreSQL защищает и от одновременных запросов |

Для календаря передавай `date_from` и `date_to` с часовым поясом. Выбираются события, пересекающие период: `ends_at > date_from AND starts_at < date_to`. Многодневное событие попадёт в каждый день, с которым пересекается.

У всех таблиц есть собственный целочисленный `id`, в том числе у таблиц связей — как ты просил. Чтобы интерес или избранное не повторялись, дополнительно стоит `UNIQUE` на пару связанных id. `FK` означает ссылку на другую таблицу; `NULL` — отсутствие значения.

`PATCH` меняет только переданные поля. Пример: `{"name":"Алексей"}` не меняет город. `{"school_id":null}` убирает школу; `{"name":null}` вернёт 422. Статус и владелец события не меняются произвольным PATCH.

`updated_at` обновляется SQLAlchemy при изменении строки; это не PostgreSQL-триггер. При ручном SQL его нужно обновлять самому. Даты хранятся как TIMESTAMPTZ; `timezone` события хранится отдельно для отображения местного времени. Цена — Decimal/NUMERIC и в JSON приходит строкой, например `"150.00"`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

По умолчанию тесты используют временную SQLite и не читают рабочую базу из `.env`. Проверки блокировок пропускаются: SQLite не поддерживает `FOR UPDATE` как PostgreSQL.

Для проверки конкурентных запросов нужна **отдельная пустая тестовая БД**, имя которой оканчивается на `_test`. Тесты удаляют и пересоздают в ней таблицы приложения. Никогда не задавай рабочую БД как `TEST_DATABASE_URL`.

```powershell
$env:TEST_DATABASE_URL = "postgresql+asyncpg://postgres:TEST_PASSWORD@localhost:5432/budvkurse_test"
.\.venv\Scripts\python.exe -m pytest -q
Remove-Item Env:TEST_DATABASE_URL
```

## Если меняешь таблицы

Правка модели Python сама по себе не меняет БД. После изменения моделей:

```powershell
.\.venv\Scripts\python.exe -m alembic revision --autogenerate -m "describe change"
# Прочитай созданный файл migrations/versions и проверь изменения.
.\.venv\Scripts\python.exe -m alembic upgrade head
```

Начальную `0001` не редактируй после применения к рабочей БД. Делай новые миграции. `downgrade` начальной миграции удаляет таблицы, поэтому это не команда обычного запуска.

## Перенос на другой компьютер или сервер

Код переписывать не нужно. На новом компьютере установи зависимости, создай PostgreSQL-базу, заполни свой `.env`, выполни миграции и запусти приложение. Если нужны старые данные — перенеси их через `pg_dump`/`pg_restore`; миграции создают структуру, а не копируют содержимое.

Также перенеси `uploads/`, если хочешь сохранить загруженные обложки. В `CORS_ORIGINS` укажи точный адрес фронтенда. Для публичного запуска нужны HTTPS, лимит частоты входа/загрузок на прокси и резервные копии; `--reload` предназначен для разработки. Секреты `.env` остаются на сервере.

## Частые ошибки

| Ошибка | Что проверить |
|---|---|
| Connection refused | PostgreSQL запущен? Правильные host/port? |
| Password authentication failed | Пароль PostgreSQL в `.env`; это не пароль аккаунта сайта |
| Database does not exist | Сначала CREATE DATABASE, потом миграции |
| Relation does not exist | Выполни `alembic upgrade head` в нужной базе |
| Relation already exists | В базе старая схема; не накладывай начальную миграцию поверх неё |
| 401 | Войди заново/обнови токены и вставь действующий access_token |
| 403 | У аккаунта нет нужной роли или объект принадлежит другому |
| 409 | Дубликат, занятые места, зависимые записи или неправильный переход статуса |
| 422 | Смотри `detail`: неверные поля, даты, координаты или связи |
| Браузер пишет CORS | Добавь адрес сайта в CORS_ORIGINS и перезапусти API |
