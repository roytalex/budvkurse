# API — примеры для проверки и подключения сайта

**После интеграции вход обязателен для всех запросов данных, включая города, темы, ленту, карту и обложки.** Авторизация также проверяется сервером. Формы сайта уже используют API и обновляют сессию автоматически.

Базовый адрес разработки: `http://127.0.0.1:4174/api/v1`. Полный список ручек — в `REFERENCE.md`; поля запросов/ответов — в `/docs` и `openapi.json`.

## 1. Регистрация и вход

`POST /auth/register`:

```json
{"email":"student@example.com","password":"MyStrongPassword123","name":"Алексей"}
```

Ответ 201 — профиль пользователя без пароля. Поле `role` принимает `student` (ученик, по умолчанию) или `organizer` (организатор). Например, добавь `"role":"organizer"` в JSON для создания организатора. Значение `admin` отклоняется с кодом 422.

`POST /auth/login`:

```json
{"email":"student@example.com","password":"MyStrongPassword123"}
```

Ответ содержит `access_token`, `refresh_token`, `token_type`. В защищённые запросы добавляй:

```http
Authorization: Bearer ACCESS_TOKEN
```

Access-токен живёт 15 минут по умолчанию. Для обновления вызови `POST /auth/refresh` с `{"refresh_token":"..."}`. Сохрани **обе** новые строки: старый refresh повторно использовать нельзя; старый access тоже перестаёт работать. Не отправляй два refresh параллельно из разных запросов фронтенда — организуй один общий запрос обновления.

`POST /auth/logout` принимает такой же объект refresh_token и отзывает сессию. `DELETE /me` деактивирует аккаунт и отзывает все его сессии. В MVP нет восстановления пароля и подтверждения email.

## 2. Города, школы и интересы

Сначала `GET /cities`. После выбора города — `GET /schools?city_id=1&page=1&limit=20`. После выбора школы — `PATCH /me`:

```json
{"city_id":1,"school_id":2,"grade":10}
```

Значения id — из ответов API, а не выдуманные числа. Школа должна принадлежать выбранному городу.

Темы загрузи через `GET /topics`. Сохранение интересов — `PUT /me/interests`:

```json
{"topic_ids":[1,3]}
```

Это замена всего списка. `[]` очищает интересы. Рекомендации `sort=recommended` поднимают события по совпадающим темам и классу пользователя; это простая сортировка, без машинного обучения.

## 3. Создание мероприятия

Зарегистрируйся с ролью `organizer` и войди. Для существующего ученика администратор может изменить роль командой из README. Организатор создаёт и публикует свои события самостоятельно. Администратор может удалить неподходящее событие.

Загрузи обложку: `POST /files`, тип тела **multipart/form-data**, поле `file`. В Swagger нажми «Choose File». Поддерживаются JPEG/PNG/WEBP до 5 МиБ и 25 мегапикселей. Сохрани `id` из ответа.

`POST /events` — пример тела:

```json
{
  "title":"Школьный хакатон",
  "description":"Соберём команду и создадим полезный проект для школы.",
  "category":"school",
  "city_id":1,
  "school_id":2,
  "cover_file_id":1,
  "topic_ids":[1],
  "starts_at":"2030-11-10T10:00:00+03:00",
  "ends_at":"2030-11-10T18:00:00+03:00",
  "timezone":"Europe/Moscow",
  "registration_deadline":"2030-11-09T20:00:00+03:00",
  "format":"offline",
  "place_name":"Актовый зал",
  "address":"Учебная улица, 1",
  "latitude":55.75,
  "longitude":37.62,
  "min_grade":8,
  "max_grade":11,
  "price":"0.00",
  "capacity":30,
  "registration_mode":"internal",
  "take_with_you":"Ноутбук и зарядное устройство"
}
```

Замени id реальными, а дату — будущей. Обложка и темы необязательны: `cover_file_id` можно убрать, `topic_ids` можно оставить пустым. Для `online` нужна `online_url` перед публикацией; для `registration_mode=external` — `registration_url`. Режим `none` означает, что запись не нужна.

Ответ 201 содержит `id` и `status=draft`. Далее:

1. Организатор: `POST /events/ID/publish` → `published`, сразу из черновика.
2. Админ: `GET /admin/events` → все мероприятия; `?status=published` → только опубликованные.
3. Админ: `DELETE /events/ID` → 204. Событие и связанные записи участников, избранное, планы, темы события и история проверки удаляются в одной транзакции.

`GET /me/events?status=draft` показывает собственные черновики. После правки опубликованное мероприятие остаётся опубликованным и обновляется сразу. Обязательные поля для публикации нельзя очистить. Организатор может удалить свой черновик или отменить опубликованное событие; удалить опубликованное может только администратор. Ручки `submit`, `reject` и `moderation` сохранены для совместимости со старыми записями; интерфейс использует прямую публикацию.

## 4. Лента, карта и календарь

Лента: `GET /events?page=1&limit=20`. Ответ:

```json
{"items":[],"total":0,"page":1,"limit":20}
```

`total` — количество по всем страницам. Когда `page * limit < total`, есть следующая страница. Максимальный `limit` — 100. Города и темы возвращаются обычным массивом; школы, события, карта и личные списки — объектом страницы.

Фильтры ленты: `search`, `city_id`, `school_id`, `category`, `topic_id`, `date_from`, `date_to`, `grade`, `age`, `format`, `price_min`, `price_max`, `place`. Сортировка: `sort=date`, `deadline` или `recommended`. Поиск ищет название/описание события, название города и школы. У гостя персональные флаги false.

Общий календарь использует ту же ручку:

```javascript
const query = new URLSearchParams({
  date_from: "2030-11-01T00:00:00+03:00",
  date_to: "2030-12-01T00:00:00+03:00",
  limit: "100"
});
const page = await fetch(`/api/v1/events?${query}`, {headers: {Authorization: `Bearer ${accessToken}`}}).then(r => r.json());
```

Используй URLSearchParams, чтобы `+03:00` корректно закодировался в URL. При большом числе событий загрузи остальные страницы. Интервал полуоткрытый: начало включается по пересечению, конец периода не включается.

Карта: `GET /events/map?west=37&south=55&east=38&north=56&page=1&limit=100`. `west/east` — долгота, `south/north` — широта. Возвращаются опубликованные очные события с координатами внутри границ. Карта поддерживает фильтры ленты. Если `west > east`, область пересекает 180-й меридиан. Ответ тоже `Page`: загрузи все нужные страницы, чтобы не потерять метки.

API отдаёт координаты мероприятий. Подложка карты, границы её прокрутки и оформление подписей остаются во фронтенде.

## 5. Избранное, планы и запись

| Действие | Запрос |
|---|---|
| Добавить в избранное | `PUT /me/favorites/ID` без тела |
| Убрать из избранного | `DELETE /me/favorites/ID` |
| Список избранного | `GET /me/favorites?page=1&limit=20` |
| Добавить в планы | `PUT /me/plans/ID`, тело `{"reminder_minutes_before":60}` |
| Личный календарь | `GET /me/plans?date_from=...&date_to=...&page=1&limit=20` |
| Убрать из планов | `DELETE /me/plans/ID` |
| Записаться участником | `POST /events/ID/registrations` без тела |
| Отменить свою запись | `DELETE /events/ID/registrations/me` |
| Свои записи | `GET /me/registrations` |
| Участники события | `GET /events/ID/registrations` — владелец/админ |

Добавление в избранное и планы не занимает место. Повторный PUT не создаёт дубль. Повторная активная регистрация возвращает 409. После отмены можно записаться снова, если остались места. `reminder_minutes_before=null` отключает сохранённую настройку напоминания; отправки уведомлений пока нет.

## 6. Обложки и подключение сайта

`cover_url` и `FileRead.url` возвращаются относительно API: например `/api/v1/files/1/content`. Если сайт открыт на порту 4174, прибавляй адрес бэкенда `http://127.0.0.1:4174`, иначе браузер запросит картинку у фронтенда.

Опубликованная обложка доступна авторизованным пользователям. Сайт загружает её с Bearer-токеном и показывает через Blob URL. Обложку черновика видит только её владелец/админ; для предпросмотра через fetch передай токен и преобразуй ответ в Blob. Удаление `DELETE /files/ID` разрешено только для файла, который не используется в мероприятии.

Минимальный клиент, который держит токен в памяти:

```javascript
const API_ORIGIN = "http://127.0.0.1:4174";
let accessToken = null;

async function api(path, {method = "GET", body} = {}) {
  const headers = {};
  if (accessToken) headers.Authorization = `Bearer ${accessToken}`;
  if (body !== undefined) headers["Content-Type"] = "application/json";
  const response = await fetch(`${API_ORIGIN}/api/v1${path}`, {
    method, headers,
    body: body === undefined ? undefined : JSON.stringify(body)
  });
  const data = response.status === 204 ? null : await response.json();
  if (!response.ok) throw new Error(JSON.stringify(data.detail));
  return data;
}

const tokens = await api("/auth/login", {
  method: "POST", body: {email: "student@example.com", password: "MyStrongPassword123"}
});
accessToken = tokens.access_token;
const events = await api("/events?city_id=1");
```

Это минимальный пример; интерфейсу ещё нужны обработка ошибок и обновление токенов. Для FormData не задавай Content-Type вручную — браузер добавит boundary. В CORS_ORIGINS сервер должен разрешать точный адрес сайта.


## Поиск географии России

Все ручки требуют входа:

- `GET /locations/search?q=Выборг&kind=city`: населённые пункты. `kind=school&city_id=ID&q=школа 12`: школы в выбранном месте. `kind=place` ищет адрес/площадку; `city_id` необязателен.
- Ответ: `items` (название, подпись, адрес, координаты, источник, подписанный `token`), `warning`, `notice`. Координаты внешнего результата ещё не означают, что место сохранено в БД.
- `POST /locations/select` с `{"token":"..."}` сохраняет выбранную школу или населённый пункт и возвращает `city` и необязательное `school`. Повторный выбор не создаёт дубль. Нельзя подменить название или координаты в токене. Результат действует 30 минут.
- `POST /locations/cities/manual`: организатор/админ передаёт `CityCreate` с `country_code=RU`, получает `city` и `school=null`.
- `POST /locations/schools/manual`: организатор/админ передаёт `SchoolCreate`, получает школу. Это создание отсутствующей записи; изменение чужих справочников не разрешается.

При недоступности Photon возвращаются локальные совпадения с предупреждением. Если их нет, ответ 503. Частые конкурентные запросы могут получить 429. Публичный источник не является полным государственным реестром. Настройка, ограничения и лицензия описаны в START.md.
