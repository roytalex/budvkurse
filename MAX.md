# Бот MAX и мини-приложение «Будь ВКурсе»

## Куда вставить токен

При запуске из VS Code открой файл `beckend/.env`:

```dotenv
MAX_BOT_TOKEN=твой_настоящий_токен
MAX_BOT_USERNAME=имя_бота_без_собачки
PUBLIC_BASE_URL=https://твой-домен.ru
MAX_WEBHOOK_SECRET=отдельный_случайный_секрет
```

В существующем локальном `.env` подготовлены поля MAX и случайный секрет webhook. Впиши токен и имя бота, замени адрес на свой публичный HTTPS-сайт. DATABASE_URL и JWT_SECRET менять не надо. `.env` исключён из Git. Токен нельзя вставлять во фронтенд, публиковать в GitHub или передавать как параметр URL. Для Docker эти параметры находятся в корневом `.env`, см. `deploy/README.md`.

Токен берётся в MAX для партнёров: Чат-боты → нужный бот → Настройки → токен. Ссылка Enigma с ошибкой 404 не заменяет токен: запроси новую у отправителя или скопируй токен из настроек.

## Запуск и подключение

Из терминала VS Code:

```powershell
cd C:\Users\roytb\Desktop\budvkurse\beckend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m scripts.setup_max --check-token
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 4174
```

Проверка токена использует значение из `.env` или спрашивает его скрытым вводом. Ничего не отправляет пользователям, только проверяет GET /me. Введённый в терминале токен не сохраняется: для работы бота запиши его в `.env`. После изменения `.env` перезапусти сервер. Если порт 4174 уже занят работающим проектом, останови старый сервер через Ctrl+C перед запуском нового. Корневой `start.cmd` также применяет миграции перед запуском.

Для настоящего MAX нужен публичный HTTPS-адрес с доступным портом 443 и доверенным сертификатом. `127.0.0.1` доступен только твоему компьютеру. Файлы Docker Compose и Caddy подготовлены в проекте; инструкция — `deploy/README.md`.

В MAX для партнёров: Чат-боты → бот → Настройки → URL мини-приложения. Укажи `https://твой-домен.ru/?max=1`, выбери кнопку «Открыть» и сохрани. Затем на работающем публичном сервере:

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_max --register
```

Для Docker: `docker compose exec app python -m scripts.setup_max --register`.

Команда проверяет доступность сайта и соответствие токена имени бота, затем подключает webhook `/api/v1/integrations/max/webhook`. Это отдельный шаг от настройки URL мини-приложения. API MAX: `https://platform-api2.max.ru`; токен передаётся в Authorization. Дополнительные доверенные сертификаты настраиваются через MAX_CA_BUNDLE: `deploy/certs/README.md`.

## Что умеет бот

- `/start`, `/help`, первое открытие — приветствие и кнопка «Открыть приложение».
- `/reminders` — кнопка открытия раздела напоминаний.
- `/stop` — отключение всех напоминаний MAX для отправителя. Не влияет на других участников и напоминания внутри сайта.
- Напоминание содержит название события, дату и время в часовом поясе мероприятия, место и кнопку «Открыть событие».

## Как участнику подключить напоминания

1. Открыть бота MAX и нажать «Открыть приложение».
2. Войти в свой существующий аккаунт сайта.
3. Открыть профиль → «Напоминания в MAX» → «Разрешить напоминания в MAX».
4. Записаться на мероприятие. Если события ещё нет в личных планах, автоматически создаётся напоминание за час. Существующая настройка сохраняется, включая «Выключено».
5. В карточке события нажать «Настроить напоминание», чтобы изменить время или выключить его.

Можно включить напоминание и для события из личных планов без регистрации. Это не записывает участником. Отмена регистрации выключает напоминание о данном событии. Удаление плана удаляет и напоминание. Связь MAX отключается в профиле; после /stop повторное согласие даётся внутри мини-приложения. Один аккаунт MAX может быть подключён только к одному аккаунту сайта.

Сервер проверяет подпись initData (HMAC-SHA256) и свежесть auth_date — не более 10 минут, с допуском часов 30 секунд. Если приложение давно открыто, закрой его и открой заново. initDataUnsafe не используется для назначения ролей или входа. Сайт по-прежнему требует email и пароль.

## Связаться с организатором

Организатор в профиле заполняет «Твой контакт MAX»: `@username`, `https://max.ru/username` или личную ссылку `https://max.ru/u/…`, скопированную из MAX. После сохранения контакт используется для всех его событий.

Участник после внутренней регистрации видит в карточке «Написать организатору в MAX». Кнопка открывает личный аккаунт организатора. До регистрации контакт не отдаётся участнику в API; после отмены записи он снова скрыт. Сам организатор и администратор имеют доступ к контакту. Внешнюю регистрацию сайт подтвердить не может, поэтому такой доступ автоматически не выдаётся. Если контакт не заполнен, карточка объясняет это вместо пустой кнопки. Сообщения между участником и организатором отправляются в MAX, чата на сайте нет.

## Доставка

Фоновая задача запускается вместе с FastAPI и проверяет напоминания каждые 30 секунд. Закрытие сайта пользователем её не останавливает; компьютер или сервер с бэкендом должен работать. При отсутствии токена задача ничего не отправляет.

Состояние попыток и успешной доставки хранится в PostgreSQL. Блокировки строк предотвращают обычную двойную отправку параллельными worker-процессами. После успешной отправки перезапуск сервера не отправляет то же напоминание снова. При переносе времени события или изменении интервала формируется новая версия напоминания. При ошибке API — повтор через 1, 2, 4 минуты и далее, максимум через час. Отменённые события, выключенные напоминания, неактивные пользователи и отключённые подключения пропускаются. Старые сообщения не отправляются позже пяти минут после начала или после окончания события.

MAX API не предоставляет используемому методу ключ идемпотентности. При аварии между принятием сообщения MAX и записью результата в БД либо неопределённом сетевом ответе редкий дубль возможен. Разные процессы бота на одном токене дополнительно требуют общего ограничения частоты; поставляемый Docker запускает один worker. Реальная доставка зависит от доступности MAX и того, не заблокирован ли бот пользователем.

## Файлы и проверки

- Бот: `beckend/services/max_bot.py`, webhook и подключение: `beckend/api/routes/max_bot.py`.
- Привязка и отправщик: `beckend/services/max_notifications.py`.
- Миграция: `beckend/migrations/versions/0005_max_notifications.py` — контакт в users, таблица max_connections, состояние доставки в plans.
- Интерфейс: `frontend/max-settings.js`, `frontend/max-shell.js`, `frontend/reminders.js`, `frontend/app-live.js`.
- Проверки: `beckend/tests/test_max_notifications.py`, `beckend/tests/test_max_integration.py`, `frontend/tests/max-settings.test.cjs`.

Тесты используют подмену ответов MAX и подписанные тестовые данные; настоящие сообщения не рассылаются. Финальная проверка на телефоне требует настоящего токена, созданного бота и HTTPS-размещения. После настройки проверь /start, вход, подключение уведомлений, напоминание, /stop и контакт организатора.

Официальные источники: [настройка API](https://dev.max.ru/docs/chatbots/bots-coding/prepare), [проверка initData](https://dev.max.ru/docs/webapps/validation/), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages), [подключение приложения](https://dev.max.ru/docs/webapps/introduction/).
