# Подключение «Будь в курсе» к MAX

Код мини-приложения готов. Бот ещё не создан, публичный сервер не выбран: реального подключения к MAX пока нет. Локальный сайт продолжает работать без бота. Для проверки компактной вёрстки открой http://127.0.0.1:4174/?max=1 — это предпросмотр, не запуск в MAX.

## Что уже сделано

- `frontend/max-shell.js` загружает официальный MAX Bridge только при запуске мини-приложения (`?max=1` или параметры MAX). Ошибка загрузки SDK не блокирует обычный сайт.
- Встроенная кнопка «Назад» закрывает меню/диалог/полноэкранную карту или возвращает в ленту. Учтены safe area, клавиатура и компактная навигация.
- Внешние ссылки открываются через MAX Bridge, QR может считываться встроенным сканером. Фото QR и ручной код остаются доступны.
- Сертификат передаётся `downloadFile()` по HTTPS-ссылке на 5 минут. Ссылка даёт доступ только к одному собственному сертификату; права и посещение повторно проверяются при скачивании. Она не является токеном входа. Сертификат HTML можно распечатать в PDF после открытия в браузере.
- В боте `/start`, `/help` и первое открытие диалога получают кнопку `open_app`. Произвольная переписка и группы игнорируются.
- Прежние аккаунты, роли и функции сохранены. Вход — по email и паролю сайта. `initDataUnsafe.user` не используется для авторизации или назначения ролей. Автовход по MAX не реализован и не имитируется.
- Параметры `calendar`, `map`, `leaderboard`, `reminders` и `event_123` открывают нужный раздел/событие после обычного входа. Проверка доступа к событию остаётся на API.

## Проверить токен и узнать ссылку на бота

В терминале VS Code:

```powershell
cd C:\Users\roytb\Desktop\budvkurse\beckend
.\.venv\Scripts\python.exe -m scripts.setup_max --check-token
```

Если MAX_BOT_TOKEN уже заполнен в beckend/.env, команда использует его. Иначе попросит вставить токен скрытым вводом: символы не отображаются, после вставки нажми Enter. Введённый токен используется только в памяти, не сохраняется в файл и не попадает в историю команд. Проверка обращается только к GET /me, не отправляет сообщения и не меняет настройки бота. Домен и webhook для неё не нужны.

Команда покажет ссылку https://max.ru/имя_бота и значение MAX_BOT_USERNAME. Успешная проверка токена не означает, что мини-приложение подключено или бот прошёл модерацию. Для подключения сохрани токен в beckend/.env и выполни шаги ниже.

Токен получают на платформе MAX для партнёров: Чат-боты → нужный бот → Настройки → копирование токена. Если доступ передали через ссылку, которая отвечает 404, попроси отправителя выдать новую ссылку или получить токен из настроек. Восстановить данные из неработающей ссылки эта команда не может.

Официальные инструкции: [настройка API](https://dev.max.ru/docs/chatbots/bots-coding/prepare), [проверка токена GET /me](https://dev.max.ru/docs-api/methods/GET/me).

## 1. Создай бота

Создай бота в [MAX для партнёров](https://business.max.ru/) и получи его имя и токен. По текущей [официальной инструкции](https://dev.max.ru/docs/webapps/introduction/) сервисы доступны подтверждённым юрлицам, ИП и самозанятым — резидентам РФ. Условия проверяются на платформе MAX, проект не создаёт и не подтверждает такой профиль автоматически.

Токен запиши только в `.env`, не в JS, GitHub или переписку. Имя `MAX_BOT_USERNAME` указывается без `@` и URL.

## 2. Размести сайт по HTTPS

Нужен публичный сервер с Docker Compose и домен, указывающий на этот сервер. Подробная инструкция и файлы: [deploy/README.md](deploy/README.md), `Dockerfile`, `compose.yaml`, `deploy/Caddyfile`. Этот вариант запускает FastAPI, фронтенд и PostgreSQL вместе. GitHub Pages не запускает Python и PostgreSQL.

Для Docker параметры находятся в корневом `.env`:

```text
DOMAIN=твой-домен.ru
ACME_EMAIL=твоя-почта
POSTGRES_PASSWORD=случайный-hex-пароль
JWT_SECRET=отдельный-случайный-hex-секрет
MAX_BOT_USERNAME=имя_бота
MAX_BOT_TOKEN=токен_бота
MAX_WEBHOOK_SECRET=отдельный-случайный-hex-секрет
```

Для запуска Python без Docker эти поля MAX записываются в `beckend/.env`; дополнительно укажи `PUBLIC_BASE_URL=https://твой-домен.ru`. Секрет webhook — 32–256 букв, цифр, `_` или `-`. Сгенерировать случайный секрет: `python -c "import secrets; print(secrets.token_hex(32))"`. Для каждого параметра используй отдельное значение.

## 3. Добавь мини-приложение к боту

В MAX для партнёров: **Чат-боты → твой бот → Настройки → URL мини-приложения**. Вставь `https://твой-домен.ru/?max=1`, выбери кнопку «Открыть» и сохрани. Этот шаг связывает сайт с ботом; регистрация webhook сама URL мини-приложения не устанавливает.

После подключения ссылка запуска: `https://max.ru/имя_бота?startapp`. Например, `?startapp=calendar` открывает календарь, `?startapp=event_123` — карточку события 123.

## 4. Подключи ответы бота

После запуска HTTPS-сайта:

```bash
docker compose exec app python -m scripts.setup_max
docker compose exec app python -m scripts.setup_max --register
```

При обычном запуске в папке `beckend`:

```powershell
.\.venv\Scripts\python.exe -m scripts.setup_max
.\.venv\Scripts\python.exe -m scripts.setup_max --register
```

Первая команда проверяет заполнение настроек. Вторая проверяет `/health`, соответствие токена имени бота и регистрирует HTTPS webhook на `/api/v1/integrations/max/webhook`. Сервер принимает события только с правильным `X-Max-Bot-Api-Secret`. Без настроек возвращает 503, с неверным секретом — 403. Повтор того же события подавляется в памяти одного процесса до 8 часов (максимум 4096 записей); после перезапуска приветствие может повториться. Поставка запускает один worker.

API MAX использует `https://platform-api2.max.ru`, токен — в заголовке Authorization. Если потребуется дополнительный CA, см. [deploy/certs/README.md](deploy/certs/README.md). TLS-проверка включена. Не отключай проверку сертификатов.

## Что проверить на телефоне после подключения

Вход ученика и организатора; создание/редактирование события; выбор города и школы; карту и календарь; напоминания; запись и QR; паспорт/сертификат; кнопку «Назад» и внешнюю регистрацию; клавиатуру в формах. Напоминания по-прежнему работают внутри открытого сайта — бот пока только запускает приложение, рассылки не добавлены.

## Проверки и ограничения

Обёртка, отсутствие обхода входа, обработка кнопки назад и разрешённых диплинков проверяются Node-тестами. Webhook, изоляция получателей и подписи сертификатов — API-тестами. Вызовы настоящего MAX пока не выполнялись: нет созданного бота, токена и публичного адреса. Docker отсутствует в текущей среде, поэтому YAML проверен, но контейнерная сборка не запускалась. Визуальный просмотр сайта инструментом браузера ранее был заблокирован политикой URL.
